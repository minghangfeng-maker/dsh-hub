## 2. 插件：两套独立

### 2.1 数据模型（迁移 123）
- **身份共用**：`plugins` 行（包名、显示名、描述、图标、主页）两平台共用，便于统计与搜索。
- **平台设置独立**：新表 `plugin_platforms(plugin_id, platform CHECK IN ('cloud','desktop'), policy, bundle_order, config_yaml, needs_restart, created_at, updated_at, PRIMARY KEY(plugin_id, platform))`。插件出现在某平台的库里 ⇔ 有该平台的行。`plugins.policy/bundle_order/config_yaml/needs_restart` 保留为**云上行的镜像**（旧代码读它不出错），写入一律经 `plugin_platforms`，由服务层同步镜像列。
- **版本独立**：`plugin_versions` 加 `platform` 列，唯一键改为 `(plugin_id, platform, version)`（SQLite 重建表；外键引用方 `user_plugins`、`desktop_plugin_targets`、`desktop_plugin_artifacts` 等一并核对）。桌面版本**必须**有 `desktop_plugin_artifacts` 整包；云上版本规则不变。
- **迁移数据**：
  1. 所有现有插件 → 云上行（policy 等照抄）；所有现有版本 → `platform='cloud'`。
  2. 有桌面整包的版本：复制一条 `platform='desktop'` 的版本行，把 `desktop_plugin_artifacts`、`desktop_plugin_targets`（及其它引用桌面版本的表）改指向新行；该插件建桌面行，policy = 原 policy（原为 `hidden` 的仍为 `hidden`）。
  3. 没有任何桌面整包的插件**不建桌面行** → 不再出现在桌面清单里（修 P1：dsh-mobile 从此不会推给桌面）。
  4. 必须在**生产库只读副本**上演练：迁移前后插件数、版本数（云上）、整包数、桌面目标数、`user_plugins` 行数逐项对账，FK/integrity ok。
- 桌面策略 → 清单 level：`required→core`、`default→default`、`optional→optional`、`hidden` 不下发（裁决 #17 不变，只是来源换成桌面行）。

### 2.2 接口（加法，缺省 cloud）
- `GET /api/admin/plugins?platform=cloud|desktop`：列表只返回该平台库里的插件，策略 / 版本 / 已装统计都按该平台。
- `POST /api/admin/plugins/:id/platforms` `{platform, policy?, bundleOrder?, configYaml?, needsRestart?}`：把已有插件加入另一平台的库；`PATCH /api/admin/plugins/:id/platforms/:platform`；`DELETE /api/admin/plugins/:id/platforms/:platform`（有该平台的下发目标或已装记录时拒绝，`?force=1` 同时撤销目标；二次密码）。
- 新建插件 `POST /api/admin/plugins` 增可选 `platform`（缺省 cloud）；版本新增接口增可选 `platform`；桌面整包上传 = 创建桌面版本（复用现有整包上传/校验/保留最近 2 版逻辑）。
- `GET /api/admin/plugins/install-stats` 已按平台分列，保持；桌面侧额外给 `bundledDevices`（上报 `source=bundled` 的设备数，用于「内置」徽标）。
- 统一下发 `DeliveryItem(kind='plugin')`：`versionId` = 云上版本，新增可选 `desktopVersionId` = 桌面版本；各自缺省 = 该平台最新。插件不在某平台库里 → 该平台进 `skippedItems`，原因「该插件不在桌面插件库 / 云上插件库」。旧请求（只有 `versionId`、两平台都选）：若该 id 是云上版本，桌面侧取桌面最新并在预览 `warnings` 里说明。

## 3. 模型：两套独立

- **共用**：渠道、模型与价格、积分、用量、中转设置（一个中转站、一套计费；桌面设备用自己的 relay key，`client_kind='desktop'` 已有）。
- **独立**：「模型配置」= 该平台的**系统预设**（可下发模型的勾选、默认模型、默认思考档位）。迁移 124：`model_presets` 加 `platform` 列（缺省 cloud），默认预设唯一性改为「每平台一个」；从当前云上默认预设复制出桌面默认预设。
- `desktopModelFragments(userId=null)` 改取**桌面**默认预设；`presetId` 必须属于桌面平台。
- **桌面基线**（客户端「自带渠道模型」的 Hub 侧保证）：迁移 124 若 `desktop_config_fragments` 里没有 `scope=all` 的 `llm-pi-ai` / `agent-default-model`，用桌面默认预设渲染写入，并生成一个新 revision。之后桌面模型配置的修改**和云上一样**：保存配置 → 统一下发 `models`（平台桌面、目标全部）→ 新 revision。保存配置本身不改清单。
- 模型页「模型配置」Tab 两平台共用同一个组件（`RelayDshTab`），只是读写的预设不同：`GET/PUT /api/admin/relay/dsh?platform=desktop`（缺省 cloud）。

### 4.1 Powered by xdedmi

### 4.2 内置插件
- 清单文件 `apps/desktop/hub/bundled-plugins.json`：`[{package, version, file, sha256, level}]`；构建时把整包复制进 `resources/hub-plugins/`，sha256 不符即构建失败。
- 首发清单：`@local/dsh-memory`（default）、`@acme/dsh-session-id`（default）、`dsh-better-sidebar`（core）、`@local/dsh-claude-pilot`（default）、`@local/dsh-codex-pilot`（default，**整包须补 LICENSE+NOTICE**，裁决 #16）。claude / codex 二进制仍在安装插件时按平台拉取（裁决 #10，不进安装器）。
- 应用规则（hub-connector）：首次启动、或内置版本高于已装版本时，从本地整包安装（与清单安装同一条 `installBundle` 路径），记 `source='bundled'` 并上报。**不需要登录**即可装好。
- 与 Hub 清单的关系：清单提到该插件 → 以清单为准（升级到更高版本、停用；非 core 可卸载）；清单不提 → 保持内置。清单给的版本低于内置版本 → 不降级，上报里写明。用户可停用非 core 内置插件。

### 4.3 内置渠道模型
- Hub 侧由 §3 的桌面基线保证：登录后第一次拉清单就有完整模型配置。
- 客户端兜底：构建时写入 `apps/desktop/hub/bundled-models.json`（桌面默认预设的快照：模型 id、显示名、默认模型、思考档位参数），由编排者用 `hub-api` 从生产导出后提交。清单里还没有模型片段时，connector 用 `/v1/models` 的结果**与快照取交集**渲染（快照提供默认模型和参数，`/v1/models` 决定该用户实际可用的模型）；清单一到即被替换。快照里**不含任何密钥**。

### 4.4 公开主页与安装包入口（WP36）
`/` 是免登录的公开主页（白色科技风 + bit 化鲸鱼背景）：右上登录/注册（已登录「进入工作台」，注册关闭时不显示注册），中间左卡 Windows 安装包、右卡安卓敬请期待，页脚 `Powered by xdedmi`。安装包信息来自公开接口 `GET /api/public/desktop/download`（`win-x64` 最新一条已发布记录，优先 `latest` 通道，否则 `nightly`；没有则按钮禁用「安装包准备中」）；`/desktop/download` 重定向到 `/`。发布 / feed 逻辑不变。

## 5. 容器列表提速（WP33）

目标：50 个实例（假驱动注入延迟：inspect 200 ms、stats 1.5 s）时，`GET /api/admin/instances` p95 < 300 ms；首屏不等 stats。
1. 一次 `docker ps -a --filter label=<hub 标签>`（驱动新增 `listManaged()`）拿全部容器的状态与标签，替代逐行 `inspect`。
2. `expectedHash`：先测出单次成本；按「用户 + 配置版本」记忆化（设置 / 插件 / 模型 / runtime 变更时失效），或至少并发计算。
3. stats **不再内联**：后台采样器维护缓存（并发 ≤ 4，运行中实例每 15 s 一轮，只在最近 2 分钟有管理员请求过列表时运转；回收器自己的每分钟采样也写入同一缓存）；列表直接带缓存值和 `statsAt`；新增 `GET /api/admin/instances/stats` 批量取，前端每 10 s 轮询刷新该列。
4. 前端：列表立即渲染，stats 列骨架占位后填充；保持现有分页/筛选。
5. 用真实 docker 只做**只读**计时（`docker ps`、对已存在容器的 `docker stats --no-stream` 单次），不起停任何生产容器。

## 6. 会话探针与休眠（WP33）

### 6.1 探针
- Hub → 容器内 DSH：`POST http://<容器地址>/api/session/list`，带 Hub 自己签发的 DSH cookie（与就绪探针相同的 `dsh-cookie` 签发），请求体 `{type:'client-request', rpcId, method:'session/list', payload:{args:{_request:{}}}}`；读 `result.value.items[].running`（上游 `SessionSummary.running`，含子代理会话）与 `updatedAt`（用户消息推进的活动时间）。分页要读全（或用上游提供的筛选），实现前先读上游 `packages/api/session-controller` 确认语义，并在生产 runtime 版本的镜像里确认该字段存在。
- 约束：只读（不 attach、不拿写租约、不创建会话——实现前在源码里确认 `session/list` 不会冷启动会话的 Agent）；超时 3 s；并发 ≤ 8；**不调用 `touchActivity`**；只探 `running` 状态的实例，绝不唤醒已停实例。
- 代理层维护每个用户当前打开的 WS 连接数（`openClients`）与最后一次断开时间。

### 6.2 状态与休眠规则（每分钟一轮）

| 状态 | 判定 | 何时停 |
|---|---|---|
| 进行中 busy | 任一会话 `running=true` | 不停；记 `lastBusyAt`。连续 busy 超过 `busyMaxMinutes`（系统设置，缺省 720，0=不限）才按 idle 规则处理，并写日志 |
| 有人在看 watching | 无 running，`openClients ≥ 1` | `now − max(startedAt, lastBusyAt, lastPromptAt) ≥ idleStopMinutes`（配额，缺省 120） |
| 无人 unattended | 无 running，`openClients = 0` | `now − max(startedAt, lastBusyAt, lastPromptAt, lastClientAt) ≥ idleNoClientMinutes`（**新配额项**，缺省 30，0=沿用 idleStopMinutes） |
| 未知 unknown | 探针失败 / 旧版 DSH 没有该字段 | 沿用旧规则（`lastActiveAt` + CPU < 3% 采满 5 个样本） |

`lastPromptAt = max(items[].updatedAt)`。开着标签页不再让实例永不休眠；没人看但 agent 在跑的回合不会被中途停掉（修 P7）。

### 6.3 存储与展示
- 迁移 102：`instances` 加 `probe_state`、`probe_at`、`running_sessions`、`last_busy_at`、`last_prompt_at`、`last_client_at`（全部可空）。
- 管理端实例列表（云上）加「会话」列：`进行中 N` / `有人在看` / `空闲 X 分钟（Y 分钟后休眠）` / `未知`；详情里显示判定依据。系统设置加 `busyMaxMinutes`；配额表单加 `idleNoClientMinutes`。
- 审计 `instance.stop` reason `idle` 的 detail 写入状态与各时间点。
