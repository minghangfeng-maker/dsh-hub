# 26 AI 助手桌面化：控制台样式 · 启动加载 · 多屏适配（WP58）

> 2026-10-30 晚，用户在 WP57e 上线后提的三条：
> 1. 对话区「纯用了手机端的逻辑」——控制台基本都在电脑上开，思考程度切换这类控件要按桌面重新设计；
> 2. 点「启动」后等待期间要有像样的 loading；
> 3. 适配不同屏幕：1080P / 2K / 4K，用户自己是 3440×2160。
>
> 涉及两个仓库：Hub（`dsh-hub`，本文件的 §2 §4 §6）与 App 网页版（`dsh-hub-app`，§3）；两边之间的约定在 §5，
> 是对 docs/24 §6 嵌入协议的**向后兼容**增补——任一边先上线都不坏。

## 0. 现状（改之前）

- AI 助手页 `/admin/assistant` = `OpsAssistantSection`（page 模式）：页标题「AI 助手」大字一行 → 卡片头（状态胶囊 + 重启）→
  `对话 | 事件 400px` 两栏，固定 `1100px` 以下变单栏。没有任何按屏幕宽度的放大。
- 对话区是 App 网页版 `/m/?embed=cockpit`（`theme` 不传 = App 自己的浅色主题；WP57d 起 Hub 用 MutationObserver 把它钉在浅色）。
  里面全是手机交互：模型 / 思考程度点了弹**底部抽屉**（ModelSheet / EffortSheet，思考程度是拖动条）、「+」弹底部抽屉、
  麦克风是「按住说话」、会话列表是左上角「航行日志」下拉、空态是「晚上好 / 今天想聊点什么？」。
- 启动：`启动` 按钮 loading + 中间一个转圈「正在启动，首次大约 1–2 分钟」；容器 `running` 后立刻换成 iframe，
  而 App 里还要再经历「交换令牌 → 等座舱节点 connectable → 建通道」，期间显示的是 App 自己的「正在连接服务器… / 助手暂时不可用 /
  暂时连不上服务器」黄条——**Hub 的状态胶囊早已是「运行中」**，两边说法对不上，看起来像坏了。
- 用户屏幕 3440 宽时（截图里设备像素比约 1），对话内容横向铺满 2000+px、字号 13–14px，空得很、字又小。

## 1. 目标与不做的事

- 目标：在电脑上像一个「运维控制台里的 AI 面板」——控件是桌面控件（下拉、分段、悬停），状态从点「启动」到能发消息一路说得清，
  1366 笔记本到 4K 都排得满、字看得清。
- 不做：Hub 管理台其他页面的整体缩放（只动 AI 助手页）；APK 与手机网页版的行为（只在 `theme=console` 下生效）；
  座舱舰桥（`theme=bridge`，已下线，不再维护但不能被改坏）。

## 2. 布局与多屏适配（Hub）

### 2.1 分档（按 Hub 页面的视口宽度 `W = window.innerWidth`，CSS 像素）

| 档 | W（CSS px） | 典型屏幕 | 布局 | 会话列表 | 事件栏宽 | 缩放 `scale` |
|---|---|---|---|---|---|---|
| S | < 1280 | 小窗口、平板横屏 | 单栏对话；事件栏收进右侧抽屉 | App 内下拉（现状） | 抽屉 420 | 1 |
| M | 1280 – 1919 | 1366/1440/1536 笔记本；4K@200% | 对话 \| 事件 | App 内下拉 | 360 | 1 |
| L | 1920 – 2559 | 1080P@100%；4K@150%（=2560 以下）；2K@125% | 会话 \| 对话 \| 事件 | **App 内常驻左栏** 248 | 400 | 1 |
| XL | 2560 – 3199 | 2K@100%；4K@150%=2560 | 会话 \| 对话 \| 事件 | 常驻 264 | 440 | 1.125 |
| XXL | ≥ 3200 | 3440/3840 宽@100%（用户这台） | 会话 \| 对话 \| 事件 | 常驻 280 | 480 | 1.25 |

- 档位是 CSS 像素，所以同一块 4K 屏在系统缩放 100% / 150% / 200% 下会落到 XXL / XL / M——这是对的：系统缩放已经放大过，就不再叠加。
- 「缩放」只放大 AI 助手这一块（卡片头、事件栏、对话区），页边距、侧边栏不动；表里的宽度是**缩放前**的值。
- 对话内容列（消息 + 输入框）在 App 里居中、最大宽 **800px**（缩放前），两侧留白；会话列表常驻时也一样。
- 档位切换用 `matchMedia` 监听，不用每帧 resize；拖窗口跨档时布局直接切，不做动画。

### 2.2 页面骨架

- 去掉页标题那一大行：`AdminPage` 的标题与助手的卡片头合并成一行
  `AI 助手  ● 就绪  · 2 项待确认 ……………… [事件]（仅 S 档） 重启  ⋯`，把高度让给对话。
- 卡片高度 = 视口高 − 顶栏 − 页内边距（撑满，不出现整页滚动条）；最小 560。
- 缩放实现：Hub 侧给卡片头与事件栏套 `zoom: var(--assist-scale)`；**不要**给 iframe 的祖先元素加 zoom
  （Chrome 会把祖先的 zoom 带进 iframe，和 App 自己的缩放叠加）。对话区的放大由 App 按 §5 的 `cockpit.layout` 自己做。
  实现后在 Chrome 里实测一次，确认 iframe 里的字号只放大了一次。

### 2.3 事件栏（桌面细节）

- 宽度按 2.1；卡片之间 12px，分组标题（待确认 / 本次会话 / 最近处理）吸顶。
- S 档：头部出现「事件」按钮（有待确认时带数字徽标），点开右侧抽屉（naive `NDrawer`，宽 420），内容与常驻栏同一组件。
- 有新的待确认方案到达且事件栏不可见（S 档抽屉关着）时，「事件」按钮抖一下 + 徽标数字变化；不自动弹抽屉。

## 3. 对话区：控制台主题（App，`theme=console`）

App 网页版在 `?embed=cockpit&theme=console` 下进入**控制台主题**：`<html class="cockpit-console" data-theme="light">`。
以下全部只在这个类下生效（APK、手机网页版、`theme=bridge` 都不受影响）。

### 3.1 主题与底色

- 强制浅色：忽略用户在 App 里的主题设置与系统深色（`stores/settings.ts` 的 `applyTheme` 看到 console 就让路，和 bridge 同一个口子）。
  做完后 Hub 那边的 MutationObserver 只作为老 App 的兜底，留着。
- 页面底色透明，透出 Hub 卡片的 `--c-surface`（白）；消息区不再有暖白底。
- 字体跟 Hub 管理台一致（系统 UI 字体栈），正文 14px、行高 1.7，缩放由 §5 `scale` 统一乘。

### 3.2 输入框（桌面版）

```
┌───────────────────────────────────────────────────────────────────┐
│ 给 AI 助手发消息…（Enter 发送，Shift+Enter 换行）                    │
│                                                                   │
│ [📎]  [DeepSeek Flash ▾]  思考 [ 低 | 中 | 高 | 超高 ]        [ ↑ ] │
└───────────────────────────────────────────────────────────────────┘
```

- 卡片：白底、1px `--border`、圆角 12、聚焦时主色描边 + 3px 主色 15% 光晕；高度自适应 2–12 行，超过出滚动条。
- **模型**：按钮显示模型短名 + ▾，点开**锚定在按钮上方的下拉面板**（不是底部抽屉）：宽 320，列表项「模型名 · 倍率 · 渠道」，
  当前项打勾；↑↓ 选、Enter 确认、Esc 关；模型超过 8 个时顶上出搜索框。没有 models 能力时按钮显示「默认模型」且不可点。
- **思考程度**：直接摆在输入框里的**分段控件**「低 | 中 | 高 | 超高」，点一下就切（沿用 `chat.pushModelSelection`，失败回滚 + toast）；
  当前模型不支持的档置灰、悬停提示原因；模型不支持思考时整个控件换成灰字「该模型不调思考」。
  每段悬停显示 `EFFORT_LEVELS[].desc`。不再用拖动条、不再弹抽屉。
- **「+」** 换成回形针图标，点开小菜单（上传文件 / 上传图片），或直接拖文件进输入框；不再弹底部抽屉。
- **麦克风**：控制台主题下隐藏（按住说话是手机交互）。
- 发送按钮 32px 圆形；流式输出时变「停止」。占位文字里带上快捷键说明。

### 3.3 会话列表

- `cockpit.layout.sessions = 'docked'`（L 档及以上）：「航行日志」从左上角下拉变成对话区里的**常驻左栏**
  （宽度按 2.1，iframe 内部渲染，顶部「＋ 新会话」，每行标题 / 发起人 / 相对时间，悬停出「⋯」菜单：重命名 / 删除，替代长按）。
- `'menu'`（M、S 档）：保持现在的下拉，但下拉里同样用悬停「⋯」，不用长按。

### 3.4 消息与空态

- 消息操作（复制 / 朗读等）悬停才出现（照搬 bridge 的做法）；用户消息右对齐气泡，助手消息铺满内容列。
- 空态换成控制台语气：标题「有什么要处理的？」+ 一行副标题「说清楚要做什么，AI 出方案，你确认后执行」+
  4 个示例按钮（点了填进输入框，不直接发）：
  「本周谁的积分消耗最多？」「最近 24 小时有哪些失败的任务？」「看一下各实例的内存占用」「把某个插件下发给所有云端用户」。
- 其余移动端专属：长按菜单、下拉刷新、底部安全区留白、PWA 安装提示、更新提示条——控制台主题下都不出现。

## 4. 启动与连接的加载（Hub 主导，App 报告进度）

### 4.1 阶段

Hub 把自己的容器状态和 App 报来的 `cockpit.status`（§5）合成一个阶段，**状态胶囊、加载卡、按钮都只看这一个值**：

| 阶段 | 判据 | 胶囊 | 加载卡上的步骤 |
|---|---|---|---|
| `idle` | 容器 stopped / missing | ○ 未启动 | —（显示「启动 AI 助手」大按钮） |
| `starting` | 点了启动，或 Hub `instance=starting` | ◌ 启动中 | ① 启动容器（进行中） |
| `booting` | Hub `running`，App 还没报 `connecting/ready`（含 App 报 `waking`） | ◌ 准备中 | ① ✓ ② 等 DSH 就绪（进行中） |
| `connecting` | App 报 `auth` / `connecting` | ◌ 连接中 | ① ✓ ② ✓ ③ 连接对话（进行中） |
| `ready` | App 报 `ready` | ● 就绪 | 加载卡淡出 |
| `offline` | ready 之后 App 报 `offline` | ◌ 重连中 | 不盖加载卡（App 自己有条幅），胶囊变黄 |
| `failed` | 启动接口报错 / Hub `instance=error` / 从点启动起 180 秒还没 ready | ✕ 启动失败 | 停在出错那一步，红字原因 + 「重试」「重启容器」 |

老 App 不发 `cockpit.status`（`cockpit.ready` 里没有 `caps`）：`running` 且收到 `cockpit.ready` 就算 `ready`（今天的行为）。

### 4.2 加载卡

- 盖在对话区上（iframe 在 `running` 后就挂上、在卡下面加载，卡淡出 200ms 时对话已经就位，不闪白）。
- 内容：三步竖排步骤条（✓ 完成 / 转圈 进行中 / 灰点 未到），右上「已用 0:42」计时，下方一行「通常 30–90 秒；首次或镜像更新后会久一些」。
- 卡后面是对话区骨架：左侧 3 行会话占位（L 档以上）、中间 3 条消息占位、底部输入框占位，带缓慢的微光动画；
  卡片头顶边一条 2px 主色不定进度条。
- `prefers-reduced-motion`：去掉微光和进度条动画，转圈换成静态图标。
- 重启走同一套（从 `starting` 开始）。
- 实测一次冷启动各阶段耗时，再据此改「通常 xx 秒」的文案。

## 5. 嵌入协议增补（docs/24 §6 的 v2，向后兼容）

- **URL**：`/m/?embed=cockpit&theme=console#code=…`。老 App 不认识 `console` → 当作不传（浅色，Hub 的兜底仍在）。
- **子 → 父**
  - `cockpit.ready` 增加可选 `caps: string[]`；新 App 发 `['status', 'layout', 'console']`。
  - 新增 `cockpit.status { phase: 'auth' | 'waking' | 'connecting' | 'ready' | 'offline' | 'blocked', message?: string }`：
    状态变化时发（去重，同一 phase 不重复发）；`ready` = 已登录 + 节点 connectable + 通道已建 + 模型列表到手（能发消息了）。
    `message` 是给人看的一句中文（不含令牌等敏感信息）。
- **父 → 子**
  - 新增 `cockpit.layout { scale: number, sessions: 'docked' | 'menu' }`：收到 `cockpit.ready` 后发一次，之后档位变化时再发。
    App 用 `document.documentElement.style.zoom = scale`（范围夹在 1–1.5）并切换会话列表形态。
- 两边的 `parseCockpitMessage` 都要校验新消息的形状；同源规则不变（docs/24 §6 两条硬约束）。
- App 侧收到未知的父消息照旧忽略；Hub 侧收到未知的子消息照旧忽略。

## 6. 验收

**Hub（WP58）**
- 五档在视口 1366×768、1920×1080、2560×1440、3440×1440、3840×2160 各截图一张（`?mock=` 场景），布局与 2.1 表一致；
  S 档 1100×800 截一张（抽屉开 / 关）。
- 启动加载：mock 场景能演示 `idle → starting → booting → connecting → ready` 与 `failed`，每个阶段截图；单测覆盖阶段合成函数
  （含老 App 无 `caps` 的兜底、180 秒超时）。
- 协议：`cockpit.status`、`cockpit.layout`、带 `caps` 的 `cockpit.ready` 的解析与发送有单测；老消息形状不回归。
- `apps/web` 全量 vitest、typecheck、lint、build 全绿。

**App（console 主题）**
- `theme=console` 下：系统深色 + 用户设了深色，仍是浅色；`theme` 不传 / `bridge` 行为不变（单测）。
- 输入框：模型下拉（键盘可操作）、思考分段（不支持的档置灰）、回形针菜单、无麦克风；截图：iframe 宽 720 / 1100 / 1600，scale 1 与 1.25。
- 会话列表 `docked` / `menu` 两种形态截图；悬停「⋯」菜单可用。
- `cockpit.status` 在冷启动全过程按顺序发出（单测模拟 auth → waking → connecting → ready，以及 ready → offline → ready）。
- APK / 手机网页版回归：相关 e2e 全过（`scripts/e2e-run.sh` 选相关的套件）。

## 7. 分工与上线顺序

- 两个仓库各改一半：Hub 侧改助手页与 `/ops` 契约，App 侧改嵌入页（`embed=cockpit` 时的布局与回执）。
- 上线：App 网页版先发（只多了一个主题与两条消息，老 Hub 不传 `console` 就完全无感），再发 Hub。
- 联调与全量回归、发版包由编排者做；子任务不发版、不合并、不碰生产。
