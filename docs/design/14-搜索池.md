# 14 搜索 / 抓取池

> 搜索与网页抓取做成 Hub 托管的池子：上游是 **DeepSeek 官方 Search/Fetch API + Tavily**，用户不用自己
> 配。开源版只保留 API key 渠道；「用 DeepSeek 账号登录后走账号余额」那条路径不在开源范围内
> （`deepseek_login` 的代码与界面已删除，迁移建的表保留未用）。

> 开源版说明：Hub 渲染的 managed patch 仍然停用 DSH 自带的 `ui-settings-account`（登录界面）与
> `llm-deepseek-account`（DeepSeek 账号模型来源），见 `models/render.ts` 的 `DISABLED_DSH_ENTRIES`——
> Hub 里没有「登录 DeepSeek 账号」这个能力了，让用户在容器里自己登录一个用不上的账号只会造成误解。

## 1. 事实依据（编排者 2026-10-18 实测 / 读源码，DSH 0.2.1-rc.2）

- `dsh-web-deepseek-api`：`POST {baseURL}/search`，请求 `{query, count, need_content:false, ori_question?}`，响应 `{results:[{url, title, snippet, date|null}]}`（任何字段类型不对 DSH 就报错）；
  `POST {baseURL}/fetch`，请求 `{url}`，响应 `{content: string}`（Markdown）。鉴权 `Authorization: Bearer <key>`；非 2xx 时 DSH 读 `error`（字符串或 `{message}`）或 `message` 拼进错误。
  配置字段 `baseURL`（默认 `https://api.deepseek.com/v1/tools`）、`apiKeyEnv`、`count`（1–50，默认 10）。选中它要在 `@deepseek-ai/dsh-web` 的 config 写 `searchProvider: deepseek-search-api`、`fetchProvider: deepseek-fetch-api`。
  会话走 `deepseek-account` 路由时它只对 `api.deepseek.com` 用账号 token，对别的 origin 用 API key——所以指向 Hub 后一律带 `HUB_MK_HUB`。
- Tavily：`POST /search`（`{query, max_results ≤ 20, search_depth:'basic'}` → `{results:[{title,url,content,score,published_date?}]}`，基础搜索 1 credit）；
  `POST /extract`（`{urls:[url], format:'markdown', extract_depth:'basic'}` → `{results:[{url,raw_content}], failed_results:[…]}`，成功 5 个 URL 计 1 credit）。Bearer 鉴权。
  额度用完 `432`（计划额度）/ `433`（按量上限），限流 `429`，无效密钥 `401`。免费额度每月 1 日重置。

## 2. 搜索池：架构

relay 模块新增「工具」子域（复用 relay 的密钥校验、内部监听器、钱包、日期工具；**不复用模型渠道表**，计费语义不同）：

```
DSH(dsh-web-deepseek-api) ──Bearer HUB_MK_HUB──► Hub /v1/tools/{search,fetch}（内部监听器 10.213.0.1:7710 与主应用都挂）
   └─ 进门检查（密钥→用户、钱包、免费额度/余额、每分钟限流）
   └─ 候选排序：渠道 priority 降序，同级按 weight + 会合哈希（同 12 §5.1）；跳过停用/冷却/不支持该工具的渠道与密钥
   └─ deepseek 渠道：原样转发 ；tavily 渠道：适配器转换请求/响应
   └─ 成功：同一事务写 relay_tool_usage + 扣费（先免费额度，再余额；扣余额同样走「先作废过期赠送 + 消费先用赠送」，13 §2）
```

## 3. 搜索池：接口与行为

### 3.1 `/v1/tools/search`、`/v1/tools/fetch`

- 鉴权同 `/v1/*`（`Authorization: Bearer sk-dsh-…`，也接受 `x-api-key`）。请求体按 §1 的 DeepSeek 格式校验，`count` 缺省 10、上限 20（Tavily 上限）。
- 错误体统一 `{"error": {"message": "...", "type": "...", "code": "..."}}`（DSH 会把 message 拼进给模型的错误里），状态码：
  无效密钥 401；总开关关 503；钱包停用 403；免费额度用完且余额 ≤ 0 → 402 `insufficient_points`（message 写「本月免费 N 次已用完，积分不足，请联系管理员充值」）；限流 429；
  请求体不合法 400；没有可用渠道 503；所有候选失败 502。
- 候选失败处理（只在没有返回给客户端任何内容前换候选，最多 `maxAttempts` 个）：
  | 上游结果 | 处理 |
  | --- | --- |
  | 2xx 且响应能转成合法格式 | 成功 |
  | 401/403（密钥无效） | 密钥 `auto-disabled` + 审计 `tools.key.auto-disable`，换下一个 |
  | Tavily 432/433（额度用完） | 密钥冷却到**下个月 1 日 00:00 UTC**，`cooldownReason=exhausted`，换下一个 |
  | 429 | 密钥冷却 `keyCooldownSeconds`（有 Retry-After 取较大），换下一个 |
  | 5xx / 超时 / 网络错 / 响应格式不对 | 密钥冷却 `keyCooldownSeconds`（`error`），渠道 `fail_streak+1`（≥ 5 熔断 60 秒），换下一个 |
  | 400/404/422 等其它 4xx；fetch 目标抓不到（DeepSeek 非 2xx 的 fetch 业务失败、Tavily `failed_results` 含该 URL 或 `results` 为空） | `client_error`：原样返回 400（message 带上游原因），**不换候选、不计费** |
- Tavily 适配：search → `{query, max_results: count, search_depth:'basic', include_answer:false}`，结果映射 `{url, title, snippet: content ?? '', date: published_date ?? null}`；
  fetch → `{urls:[url], format:'markdown', extract_depth:'basic'}`，`results[0].raw_content` → `{content}`。`ori_question`、`need_content` 对 Tavily 忽略。
- 计费：每次**成功**调用：当月已用 < `freeCallsPerMonth` → `free=1, cost=0`；否则 `cost = searchPriceMicro / fetchPriceMicro`（钱包倍率 `rate_percent` 照样乘，向上取整）。当月按 Asia/Shanghai 自然月。
  不成功的调用记一条 usage（cost 0、`free=0`），不占免费额度。
- 每用户每分钟 `perUserPerMinute` 次（内存滑动窗口）。

### 3.2 管理与用户接口

见 `packages/shared/src/api/tools.ts` 与 `contract-map.ts`「14 §3」段：设置、概览、渠道 CRUD + 测试、批量加密钥（每行一把、按 sha256 去重）、改/删密钥（含清除冷却）、用量分页；用户端 `GET /api/me/tools`、`/api/me/tools/usage`。
审计：`tools.settings.update`、`tools.channel.create|update|delete`、`tools.key.add|update|delete|auto-disable`。密钥 AES-GCM 加密存（同 `relay_channel_keys`），只回显末 4 位。

### 3.3 对账不变量（扩展 12 §6.4）

`balance = Σ ledger.amount − Σ relay_usage.cost − Σ relay_tool_usage.cost`（按用户），测试钉住。工具费用**不进** `total_spent`、不进 `relay_usage_daily`（日上限只管 token）。

## 4. 搜索池：数据模型（迁移 `085_relay_tools.sql`，relay 段）

```sql
CREATE TABLE relay_tool_channels (
  id INTEGER PRIMARY KEY,
  kind TEXT NOT NULL CHECK (kind IN ('deepseek','tavily')),
  name TEXT NOT NULL UNIQUE,
  base_url TEXT NOT NULL,
  tools_json TEXT NOT NULL,                    -- ["search","fetch"]
  priority INTEGER NOT NULL DEFAULT 0,
  weight INTEGER NOT NULL DEFAULT 1,
  timeout_ms INTEGER NOT NULL DEFAULT 30000,
  proxy_url TEXT,
  search_cost INTEGER NOT NULL DEFAULT 0,      -- 微积分，我方成本估算
  fetch_cost INTEGER NOT NULL DEFAULT 0,
  enabled INTEGER NOT NULL DEFAULT 1,
  note TEXT NOT NULL DEFAULT '',
  fail_streak INTEGER NOT NULL DEFAULT 0,
  cooldown_until TEXT,
  last_error TEXT,
  last_error_at TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE TABLE relay_tool_keys (
  id INTEGER PRIMARY KEY,
  channel_id INTEGER NOT NULL REFERENCES relay_tool_channels(id) ON DELETE CASCADE,
  label TEXT NOT NULL DEFAULT '',
  key_enc TEXT NOT NULL,
  key_hash TEXT NOT NULL,
  last4 TEXT NOT NULL,
  state TEXT NOT NULL DEFAULT 'active' CHECK (state IN ('active','disabled','auto-disabled')),
  cooldown_until TEXT,
  cooldown_reason TEXT CHECK (cooldown_reason IN ('rate-limit','exhausted','error')),
  last_error TEXT,
  last_error_at TEXT,
  last_used_at TEXT,
  created_at TEXT NOT NULL,
  UNIQUE (channel_id, key_hash)
);
CREATE TABLE relay_tool_usage (
  id INTEGER PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  key_id INTEGER,                              -- 用户 sk-dsh 密钥（逻辑引用 relay_keys）
  tool TEXT NOT NULL CHECK (tool IN ('search','fetch')),
  status TEXT NOT NULL CHECK (status IN ('ok','client_error','upstream_error','rejected')),
  free INTEGER NOT NULL DEFAULT 0,
  cost INTEGER NOT NULL DEFAULT 0,
  channel_id INTEGER,                          -- 最后一个候选（逻辑引用）
  tool_key_id INTEGER,
  upstream_cost INTEGER,
  attempts INTEGER NOT NULL DEFAULT 0,
  duration_ms INTEGER NOT NULL DEFAULT 0,
  summary TEXT NOT NULL DEFAULT '',            -- 搜索词前 64 字 / URL 前 200 字
  error TEXT,
  month TEXT NOT NULL,                         -- 'YYYY-MM'（Asia/Shanghai）
  created_at TEXT NOT NULL
);
CREATE INDEX relay_tool_usage_user_month ON relay_tool_usage(user_id, month);
CREATE INDEX relay_tool_usage_created ON relay_tool_usage(created_at);
```

- 「本月免费已用」= `COUNT(*) WHERE user_id=? AND month=? AND free=1`；「某密钥本月调用」= 按 `tool_key_id` + `month` 统计 `status='ok'`。
- 设置存 settings 键 `relay_tools`（`ToolSettingsSchema`）。逐条用量按 `relay.logRetentionDays` 一起清理（清理只删 `created_at` 早于保留期且 `month` 不是当月的行，免得免费额度计数被删掉）。

## 5. 搜索池：下发到 DSH

`deliverToDsh = true` 且 `enabled = true` 时，在用户的 `managed.patch.yml` 里加（写法照 models 渲染里已有的插件/配置输出方式，以真容器验证为准）：

```yaml
- name: '@deepseek-ai/dsh-web'
  config:
    searchProvider: deepseek-search-api
    fetchProvider: deepseek-fetch-api
- name: '@deepseek-ai/dsh-web-deepseek-api'
  config:
    baseURL: http://10.213.0.1:7710/v1/tools      # relay.internalBaseUrl() + '/tools'
    apiKeyEnv: HUB_MK_HUB
```

- `HUB_MK_HUB` 已经由 hub-relay 注入（12 §7.0）；没有 hub-relay 提供方的用户也要注入它（复用 `containerEnv()`，必要时签发 system 密钥）。
- 这部分进入 managed 配置的哈希：开关变化 → 实例显示「配置已更新，重启后生效」；管理员用现有下发（rollout，kind=models）让它生效。
- **必须用真容器验证**：渲染后起一个测试容器（命名 `dshhub-test-wp18a-*`，测试网段），确认没有 ValidationError，并从容器里对假上游真实跑一次 `web_search`（或至少用 `dsh --dump-config` 之外的方式确认 provider 被选中，例如容器日志 / 调用 Hub 的计数增加）。
