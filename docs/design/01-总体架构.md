# 01 总体架构

## 1. 组件

| 代号 | 组件 | 运行位置 | 职责 |
| --- | --- | --- | --- |
| E | **edge**（边缘转发，可选） | 公网入口（同一台主机，或云上的入口机器/负载均衡） | 四层转发：对外 `:443`（或任选端口）→ 本机 127.0.0.1:7443；L4，不解密；可附加 PROXY protocol v1 头（00 D18–D22） |
| T | **tunnel**（反向隧道，可选） | Hub 主机发起 | 隧道客户端（frp、`ssh -R`、云厂商负载均衡的后端注册等，任选其一）：把本机 127.0.0.1:7443 暴露到公网入口；断线自动重连 |
| A | **hub-api** | Hub 主机（Linux），systemd 用户服务 | 唯一的应用进程：TLS 终止、静态前端、REST/SSE、DSH 反向代理、任务引擎、容器编排 |
| W | **hub-web** | 构建产物由 hub-api 托管 | Vue3 单页应用：用户端 + 管理端 |
| R | **runtime 镜像** | Docker | `dshhub/runtime:<DSH 版本>`：Node 24 + 全局 `@deepseek-ai/dsh` + pnpm + 常用工具 + 入口脚本 |
| U | **用户容器** | Docker 网络 `dshhub-users` | 每用户一个，跑 `dsh --profile web` |
| D | **Docker Engine** | Hub 主机（同一台机器） | 容器、网络、镜像构建 |

刻意**只有一个应用进程**（hub-api）：不引入 Caddy/Nginx/Redis，单机部署的运维面尽量小。
需要横向拆分时，代理层与任务引擎都是独立模块，可以搬出去。

## 2. 网络拓扑与端口

最小形态没有反向代理：Hub 只监听回环，本机浏览器直接开（或让前端 dev 服务器代理 `/api`）。
要对外就在前面加一层代理（同机、另一台入口机器或云厂商负载均衡都行）：四层透传、七层终结，或用隧道把
Hub 主机的端口映到公网入口；对外端口按需选（443 或任意端口）。两种接法见 08 §3。

```
                       ┌───────────── 同一台 Linux 主机 ─────────────┐
浏览器 / App ──TLS──▶  反向代理（可选）                                  │
                       ├─ 四层透传 + PROXY v1 ──▶ 127.0.0.1:7443  TLS 网关 │
                       └─ 七层终结 + X-Real-IP ─▶ 127.0.0.1:7720  边缘入口 │
                                                          │             │
                                              127.0.0.1:7700  hub-api    │
                                                          │             │
                                        ▼ 直连容器 IP（宿主不发布容器端口） │
                              容器网络 dshhub-users（HUB_USERS_SUBNET）    │
                                 dshhub-<slug> : 3000  ×N                │
                       └────────────────────────────────────────────────┘
                                       │
                                  Docker Engine（本机 socket）
```

| 位置 | 端口 | 绑定 | 用途 |
| --- | --- | --- | --- |
| 本机 | 7700 | 回环 | hub-api 明文 HTTP（本机调试、Vite 代理；**不经隧道暴露**） |
| 本机 | 7443 | 回环 | hub-api TLS 网关（要求 PROXY v1；同端口明文请求 301），`HUB_TLS_PORT=0` 时关闭 |
| 本机 | 7720 | 回环 | hub-api 边缘入口（前置代理终结 TLS 后转发，只认 `X-Real-IP`），`HUB_EDGE_PORT=0` 时关闭 |
| 本机 | 7710 | 容器网络网关 IP | 中转站内部监听器（容器访问 `/v1/*` 与 `/ops/*`） |
| 本机 | 5171 | 回环 | 前端开发服务器（仅开发期） |
| 容器 | 3000 | 容器 IP | 用户 DSH（宿主不发布端口，由 hub-api 反向代理） |

真实域名只写在部署方的配置里（`hub.env`），仓库与文档里一律用 `hub.example.com` 之类的示例值。

**模块边界规则**：模块之间只通过各自 `index.ts` 导出的 service 接口互相调用；

## 5. 关键数据流

### 5.1 注册 → 第一次打开 DSH

```
浏览器 POST /api/auth/register（邀请码）
  → auth：校验邀请码/用户名/密码强度/限流 → 写 users(status=active|pending) → 消耗邀请码 → 审计
  → instances.provision(user)：建目录 users/<slug>/{home,workspace,managed}，渲染 managed.patch.yml
  → 返回会话 cookie（hub_sid）
浏览器进入「我的工作台」→ 点「打开 DSH」
  → POST /api/me/instance/start → instances.ensureRunning()
      · 若无容器：按用户的 runtime 版本、配额、模型密钥 env 创建容器 → 启动
      · 等就绪：容器 IP:3000 可连 → DSH 已写出 browser-session 密钥 → 用密钥签 cookie → GET / 返回含 __DSH_BOOT__
      · 首次启动后：应用「必装/默认」插件（pnpm install）→ 重启 DSH（仅首次，约 +20s，界面显示进度）
  → 前端新标签打开 /dsh/<用户名>/（slug 只用于容器名/数据目录，不再出现在对外地址里）
浏览器 GET /dsh/<用户名>/...
  → proxy：校验 hub_sid 的用户名与路径一致（不是主人/用户名不存在都 404）→ 去前缀 → 改写 Host/Origin 为 dshhub-<slug>:3000
    → 注入现签 DSH cookie → 转发到 容器IP:3000（HTTP/WS/SSE）→ HTML 注入 ownsHost
    → 记录活跃时间（节流 30s）
旧地址 GET /u/<slug>/...：校验会话属于该 slug 的主人后 301 到 /dsh/<用户名>/...（子路径与查询串保留）
```

### 5.2 管理员一键下发插件

```
管理员 POST /api/admin/rollouts {kind:'plugin', action:'install', pluginId, versionId, targets:{all:true}, strategy:{canary:1, concurrency:3}}
  → rollouts 建 job + 每用户一条 task → jobs 引擎按策略执行：
      金丝雀 1 个 → 成功后放量，并发 3；失败率超阈值自动暂停
      每个 task：改 profile package.json → 容器内 pnpm install（容器停着就起一次性维护容器）→ 需要时重启 DSH → 健康检查 → 记录 user_plugins
  → SSE 推送进度到管理后台「任务中心」；失败可「重试失败项」
```

### 5.3 统一更新 DSH

```
管理员「DSH 版本」→ 输入/选择版本 0.2.1 → 构建镜像（任务，实时日志）→ 设为默认
  → 下发任务 {kind:'runtime', runtimeId, targets, strategy}
      每个 task：记录旧镜像 → 停容器 → 用新镜像重建（卷不变）→ profile 依赖重装 → 启动 → 健康检查
                 失败 → 用旧镜像重建回滚 → task 标记 failed（附日志）
```

### 5.4 打包下载

```
用户 POST /api/me/exports {parts:['workspace','sessions','settings'], format:'zip'}
  → jobs 引擎（每用户串行、全局并发 2）→ 直接读宿主卷，流式写 exports/<slug>/<id>.zip（不经容器）
  → 完成后前端收到 SSE → 「下载」按钮 → GET /api/me/exports/:id/download（支持 Range 断点续传）
  → 24 小时后清理
```

## 6. 配置（环境变量）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `HUB_DATA_DIR` | 开发：`<repo>/.data`；生产：`/srv/dsh-hub` | 所有数据的根，见 03 §2 |
| `HUB_HTTP_PORT` | `7700` | 明文 HTTP（回环） |
| `HUB_TLS_PORT` | `0`（关闭） | TLS 网关；要对外时设 7443 |
| `HUB_REDIRECT_PORT` | `0` | 独立的 HTTP→HTTPS 跳转监听器——**不使用**（明文跳转在 7443 同端口完成） |
| `HUB_PROXY_PROTOCOL` | `true`（仅作用于 7443） | 是否要求 PROXY v1 头 |
| `HUB_PUBLIC_ORIGIN` | `http://127.0.0.1:7700` | 生成链接、公网 Origin 校验、cookie Secure 推断 |
| `HUB_HSTS_MAX_AGE` | `86400` | 只对经 7443 的公网响应发 HSTS；`0` = 不发 |
| `HUB_COOKIE_SECURE` | 不设 = 按监听器决定（7443 加 Secure，7700 不加） | 显式设置时一律以它为准 |
| `DOCKER_HOST` | `unix:///var/run/docker.sock` | 容器引擎地址；也兼容 podman 套接字 |
| `HUB_CONTAINER_DRIVER` | `docker` | `docker` / `fake`（测试与无 Docker 开发） |
| `HUB_USERS_NETWORK` | `dshhub-users` | |
| `HUB_CONTAINER_PREFIX` | `dshhub-` | 容器名 = 前缀 + slug；开发/测试用 `dshhub-test-` |
| `HUB_ENV_ID` | `prod` | 写入容器标签 `dshhub.env`；对账/空闲回收/stop-all 只处理本环境容器（无该标签的旧容器视为 `prod`） |
| `HUB_USERS_SUBNET` | `10.213.0.0/16` | 首次创建网络时使用；出网防火墙按它匹配，避开 Docker 默认地址池 |
| `HUB_NPM_REGISTRY` | `https://registry.npmmirror.com` | 构建镜像与容器内 pnpm 使用 |
| `HUB_LOG_LEVEL` | `info` | |

密钥类配置**不走环境变量**，统一放 `HUB_DATA_DIR/secrets/`（0600，首次启动自动生成）：
`master.key`（加密 API Key）、`session.key`（会话 HMAC，可选）、`tls/`（acme.sh 装进来的 `fullchain.pem`/`privkey.pem`，或 Hub 生成的临时自签证书）。
