# 10 验收标准

每条写成「操作 → 期望」。A 组是**对外开放注册前的硬闸门**，由部署者在普通终端执行（会话不做逃逸测试）。

## A. 安全闸门（`scripts/security-gate.sh` 自动执行 A1–A10，输出 PASS/FAIL）

| # | 检查 | 期望 |
| --- | --- | --- |
| A0 | `sudo nft list table inet dshhub` | 规则已加载且与 02 §4 一致 |
| A1 | 测试容器（与用户容器同规格，不挂用户数据）内 `ls /mnt 2>&1`、检查宿主磁盘挂载点 | 均不存在 |
| A2 | 容器内 `ls <宿主用户的家目录> 2>&1`（`scripts/security-gate.sh` 用 `HOST_HOME`，默认 `$HOME`） | 不存在 |
| A3 | **（仅在 WSL 上部署时适用，其它环境记 N/A）容器内执行一个 Windows PE 程序**（脚本把 `/mnt/c/Windows/System32/whoami.exe` 复制进测试容器，分别在 2 层子 shell 中、在 tini 下执行） | 均失败；**任何一次出现 Windows 侧输出即 FAIL**，不得开放注册，走 B 计划（02 §3） |
| A4 | 容器内 `curl -m 5 http://192.168.1.1/`、`http://<宿主局域网 IP>:<宿主上其它服务的端口>/` | 超时/拒绝 |
| A5 | 容器内连网关 IP（10.213.0.1）与宿主局域网 IP 上的 7700、7443 以及宿主其它常用端口（如 22） | 全部失败；网关 53 端口 DNS 正常 |
| A6 | 容器 A 连容器 B 的 IP:3000 | 失败（nftables forward 规则） |
| A7 | 容器内 `curl -sS -o /dev/null -w '%{http_code}' https://api.deepseek.com/` | 有 HTTP 状态码（出网正常） |
| A8 | 容器内 `curl -sS https://registry.npmmirror.com/ -o /dev/null -w '%{http_code}'` | 200 |
| A9 | `docker inspect` 用户容器：`CapDrop=[ALL]`、`SecurityOpt` 含 `no-new-privileges`、`Memory`/`NanoCpus`/`PidsLimit` 与配额一致、无 docker.sock 挂载、`PortBindings` 为空 | 全部符合 |
| A10 | 容器内 `node -e "const a=[];for(;;)a.push(Buffer.alloc(1e7))"` | 仅该容器 OOM；其他用户 DSH 仍可访问 |

## F. 公网与部署（阶段二：对外入口上线）

`hub.example.com` 代指真实域名；例子按 443（默认端口）写，若用非标准端口（如 `8443`），各条 URL 里带上端口即可。

| # | 操作 | 期望 |
| --- | --- | --- |
| F1 | 手机 4G 打开 `https://hub.example.com/`（**不装任何证书**） | 无证书警告（Let's Encrypt）；登录、打开 DSH、对话全流程可用（含 WS、SSE） |
| F2 | `curl -sI http://hub.example.com/some/path` | `301`，`Location: https://hub.example.com/some/path` |
| F3 | 手机登录后看审计日志与「登录设备」 | 显示手机的真实公网 IP（PROXY protocol 生效） |
| F4 | 停掉 Hub 主机上的隧道客户端 / 断开反向代理（如 `systemctl --user stop <隧道服务>`），30 秒后再起 | 停的期间公网连不上；启动后 15 秒内恢复（断线自动重连） |
| F5 | 公网入口机器上 `ss -ltnp` | 对外只开代理端口（443 或所选端口）；隧道落地端口只绑 127.0.0.1；`find / -name 'privkey.pem' -path '*dsh*'` 无结果，公网入口上无 Hub 证书/密钥/数据 |
| F6 | 主机重启（在 WSL 上部署时：`wsl --shutdown` 后重新登录 Windows） | Hub、证书定时器、出网规则、隧道客户端全部自动恢复 |
| F7 | Hub 主机上 `~/.acme.sh/acme.sh --renew -d hub.example.com --ecc --force` | 不重启 Hub；`openssl s_client -connect hub.example.com:443 -servername hub.example.com` 看到新证书序列号；已打开的页面不断 |
| F8 | 公网发 `curl -X POST -H 'Origin: http://localhost:5173' -H 'Content-Type: application/json' https://hub.example.com/api/auth/login -d '{}'` | 403（公网只认 `HUB_PUBLIC_ORIGIN`）；本机 7700 同样请求不被 Origin 拦 |
| F9 | 公网同一 IP 连续 11 次错误登录 | 第 11 次被限流（公网请求不享受回环豁免） |
| F10 | 本机浏览器打开 `http://127.0.0.1:7700` 登录 | 仍然可用（本机 cookie 不加 Secure） |
| F11 | 入口机器上原有的其它站点（如果同一台机器还在跑别的服务） | 上线前后都正常，未受影响 |
