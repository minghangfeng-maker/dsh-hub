# 25 下发流程重做 · 云端/桌面端切换的视觉区分 · 座舱下线（WP57）

> 2026-10-30 用户原话要点：①座舱想做好看太难，**先在界面上下线**；②下发「杂糅在一起」不好用，按
> **模型 → 云端/桌面端 → 配置 → 下发 → 完成** 的思路重做；③不同端切换没有明显的动效区分。
> 本文是设计说明；与 `docs/21`（统一下发）、`docs/22 §1.2`（平台切换）冲突处以本文为准。**后端与契约不改。**

## 0. 现状梳理（改之前）

管理台侧边栏四组：概览 / 人与环境（用户、实例）/ 能力下发（统一下发、插件、DSH 版本、模型、Claude Code、Codex、
搜索池、任务中心）/ 系统。带「云上 | 桌面」切换的页面：实例、插件、插件详情、DSH 版本、模型、
Claude Code、Codex、任务中心。

下发的问题：

| # | 问题 | 位置 |
|---|---|---|
| P1 | 第 1 步一屏同时回答四件事：平台（可多选）+ 插件（多选、每个两套版本下拉）+ 模型配置（勾一下）+ DSH 版本 | 旧 `DeliveryItemsStep` |
| P2 | 模型配置要在「模型 · 模型配置」里改、保存，再跳到向导里**重新选一遍平台和内容**才能下发 | `RelayDshTab` →  `/admin/rollouts` |
| P3 | 动作（安装/升级/卸载/仅应用配置）和目标挤在第 2 步，动作还要按内容联动禁用，看不出为什么灰 | 旧 `DeliveryTargetsStep` |
| P4 | 两个端同时选时，插件要配两套版本、预览按两个端分组，一次提交混着两种执行语义（实例 = 任务，桌面 = 清单版本） | 旧向导 |
| P5 | 「云上 / 桌面」是 Naive 的单选按钮，切换只换了按钮高亮，页面本身没有任何变化，经常不知道自己在哪个端 | `PlatformSwitch` |

## 1. 座舱下线（只下线界面）

- `/admin` 重定向到 `/admin/overview`；侧边栏去掉「回到座舱」；用户菜单「管理后台」直接进概览。
- 座舱的代码、后端模块、App 的嵌入模式都保留；路由导出为 `COCKPIT_ROUTE`（不注册，座舱测试自己挂），恢复时放回 `routes` 即可。
- 座舱容器只在打开座舱页（`GET /api/admin/cockpit/state`）时才会被拉起，下线后不再自动起；**生产上已经在跑的座舱容器不会自己停**，要省内存可在「实例」里停掉 `hub-ops`。

## 2. 下发：五步，一次「一类内容 × 一个端」

`/admin/rollouts`（侧边栏改名「下发」）。顶部五步条，走过的步骤显示已选的值，点一下回到那一步；底部固定操作条（上一步 / 摘要 / 下一步或确认下发）。

| 步 | 回答的问题 | 内容 |
|---|---|---|
| 1 内容 | 发什么？ | 三张大卡：模型配置 / 插件 / DSH 版本（卡上是数据：已选几个模型、库里几个插件、当前默认版本）。点了直接进下一步 |
| 2 端 | 发到哪一端？ | 两张大卡：云端（蓝）/ 桌面端（紫），单选。DSH 版本的桌面端卡置灰并写明原因。选定后整页换成该端的颜色 |
| 3 配置 | 下发哪些模型？ / 怎么处理哪些插件？ / 升级到哪个版本？ | 模型：**就是「模型配置」那张表**（嵌入模式），勾模型、设默认，下一步时自动保存。插件：动作三选一（安装/升级/卸载）+ 只列当前端插件库、只给当前端版本。版本：一个下拉 |
| 4 下发 | 发给谁？ | 全部 / 指定用户 / 角色 / 已安装用户 / 条件筛选；云端多一个折叠的「灰度策略」；预览**自动刷新**（改目标 350 ms 后重算）；「确认下发」走二次密码 |
| 5 完成 | — | 勾号动画；云端 = 任务链接，桌面端 = 清单 #revision 与设备数；整项跳过；**再下发到另一端**（内容、动作、目标带过去，回到「配置」，插件版本换成那一端的最新）/ 去任务中心 / 新的下发 |

规则（纯函数在 `composables/delivery-draft.ts` 的「五步流程」一节，有单测）：

- 模型配置的动作固定为「仅应用配置」；DSH 版本固定「升级」且只能云端；插件选「升级」时目标默认「已安装且版本较旧」，选「卸载」时目标清空必须自己选。
- URL 预填（各页面的「下发」按钮不用改）：内容和端都有 → 从「配置」开始；只有内容 → 从「端」开始；都没有 → 从「内容」开始。混了几类只留第一类；两个端都带（插件库「升级」按钮）先发第一个，完成页的「再下发到另一端」直接指向第二个。
- 请求体仍是契约的 `DeliveryRequest`（`platforms` 一个元素、`items` 一类），后端零改动。

## 3. 端的视觉区分

- 令牌：`--c-plat-cloud #4262f0`（品牌蓝 hover 档）、`--c-plat-desktop #7a5af5`（紫罗兰压深一档），各带 `-soft` / `-ink`，实色上白字对比度 ≥ 4.5:1。
- `PlatformSwitch`：胶囊分段 + **滑块**，切换时滑块平移并换色（320 ms）；文案统一为「云端 | 桌面端」；方向键可切。
- `AdminPage` 新属性 `platform`：①页面顶部端色光晕（云端左上蓝、桌面端右上紫，交叉淡入）；②切换右侧一条端色导轨；③换端时内容区从切换方向滑入（去桌面端从右进、回云端从左进，380 ms；内容不重新挂载）。所有带切换的页面都接上了。
- 下发流程里步骤条、按钮、卡片、完成页勾号都用当前端色；步骤间前进从右滑入、后退从左滑入。
- `prefers-reduced-motion`：只保留 ≤120 ms 淡入。
- 管理端可见文案「云上」统一为「云端」（公开主页 / 文档里面向用户的「云上 DSH」不动）。

## 5. AI 助手进概览（2026-10-30 下午，用户手绘：概览下方「对话 | 事件卡片」）

座舱的 UI 下线后，保留它「和 AI 说 → AI 出方案 → 管理员一键确认执行」的能力，换成经典管理台里的一个区块：

```
概览：统计卡 → 宿主资源
┌ ✦ AI 助手 · 运行中 · 1 项待确认 ─────────────────────── 启动 / 重启 ┐
│ 对话（App 网页版 /m/ 嵌入，浅色主题）     │ 事件卡片                  │
│                                          │ 待确认：方案卡 / 密钥卡    │
│                                          │ 本次会话：AI 投放的图/表   │
│                                          │ 最近处理：已执行/拒绝/失败 │
└──────────────────────────────────────────┴──────────────────────────┘
最近注册 / 正在进行的任务 / 最近审计
```

- 组件 `components/admin/assistant/OpsAssistantSection.vue`；复用座舱的 `CockpitFrame`（`theme=null` → App 自己的浅色）、`ProposalCard`、`SecretRequestCard`、`CanvasCard`，外层给一套浅色的 `--b-*` 令牌。
- **点了才启动**：`GET /api/admin/cockpit/state?start=0` 只读状态不拉起（新参数，缺省行为不变）；「启动」走已有的 `POST /ops-instance/start`。
- **空闲会停**：Hub 空闲回收不再跳过座舱容器（与普通实例同一套规则：会话在跑不停，没人看着 `idleNoClientMinutes` 后停）。
- 能力层、方案、审计、reauth 全部沿用 docs/24，没有改。
- 已知：对话里 App 的个别文案还是舰桥叫法（如「已投放左舷」），要改得发 App 网页版，下次改 App 时一起。

### 5.1 调整（2026-10-30 16:xx，用户三条反馈）

1. **独立成页**：`/admin/assistant`「AI 助手」，侧边栏紧挨在「概览」下面；概览不再放这个区块。
2. **白底**：对话区与事件栏都用 `--c-surface`；嵌入的 App 浅色主题本来是暖白 `#f9f8f6`，`CockpitFrame` 新属性 `pageBackground`
   在 iframe 加载后往它的 `<head>` 写 `:root{--bg:<本页 --c-surface 的值>}`（同源，不改 App）。
3. **事件栏「清空」**：记一个时刻（`localStorage['hub.admin.assistant.clearedAt']`，按浏览器），此前的「本次会话」结果卡与已处理 /
   已过期的方案不再显示；**还能拍板的待确认方案与密钥请求保留**（要去掉就点「拒绝」/「取消」）。服务端记录与审计不动。
