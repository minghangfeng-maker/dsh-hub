# 19 「积分与用量」页改版（用户端 `/usage`）

> 2026-10-20 用户需求：「个人的用量部分……现在页面有点杂，整体从上到下变成积分情况，然后模型消耗情况，这里图做的更细致一些，
> 可以让用户加筛选条件，以及多个模型的曲线图，然后放可用模型列表，然后是放搜索与抓取，只用展示用量，不需要具体细则，
> 然后把外接部分先隐藏，不要这部分，然后最后放使用记录。然后积分流水部分，也可以暂时去掉，以后我们再规划充值部分。」
> 任务包 WP24（前端为主 + 一个后端加法字段）。契约：`relay.ts` 的 `RelayUsageStatsResponseSchema.dailyByModel`（标了「19」）。

## 0. 决策

| # | 决策 |
| --- | --- |
| D1 | 页面从上到下**只有五块**：① 积分 → ② 模型消耗 → ③ 可用模型 → ④ 搜索与抓取 → ⑤ 使用记录。页头只有标题和「刷新」 |
| D2 | **去掉**「积分流水」卡（以后和充值一起重做）。`LedgerTable` 组件与 `/api/me/relay/ledger` 接口保留不删（管理端在用；以后充值页再用） |
| D3 | **隐藏**「外接」：「API 密钥」「接入说明」两张卡不渲染。组件、接口、mock 都保留；`UsageView.vue` 里用一个常量 `SHOW_EXTERNAL_ACCESS = false` 控制，以后改成 `true` 即恢复原样。DSH 内置密钥照常自动注入容器，不受影响 |
| D4 | 「搜索与抓取」**只显示本月用量**：免费额度进度条、本月调用次数、本月花费。去掉「超出后单价」「下发到 DSH」两格、卡内说明文字和逐条明细表 |
| D5 | 逐条明细统一收进最后的「使用记录」：标签页「模型调用 / 搜索与抓取 / 算力租赁」。后两个标签只在有内容时出现（搜索池开着；算力计费开着或租过），只有一个标签时不显示标签头 |
| D6 | 「模型消耗」图改成**自绘 SVG 多模型折线图**（不引图表库，与现有 `DailyUsageChart` 一致），加筛选；数据来自新的 `dailyByModel`（§3），一次请求拿全，筛选模型/指标/图形在前端切换不重新请求 |

## 2. 各块规格

### 2.1 ① 积分

- 沿用 `RelayStatsCards`（三格：余额 / 今日 / 本月），放进一个整体区块，卡片之间视觉统一；余额为负/偏低时的颜色与一句提示保持现状（这是状态提示，不是常驻说明）。
- 页面顶部的红色 `NAlert` 和卡内的负余额提示重复了——**只留卡内那一句**，删掉 `NAlert`。
- `wallet.dailyBonusLeftMicro > 0` 时，余额格下面加一行数据「今日赠送剩余 x.xx 积分」（数据行，不是说明）。
- 余额格的 InfoTip「1 积分 = 1 元……」保留。

### 2.2 ② 模型消耗（重点）

**筛选条（一行，窄屏自动换行；07 §2.8 控件内文字不断行）**

| 控件 | 选项 | 默认 | 说明 |
| --- | --- | --- | --- |
| 时间 | 7 天 / 30 天 / 90 天 / 自定义 | 30 天 | 自定义 = `NDatePicker type="daterange"`，最长 92 天（`RELAY_MAX_RANGE_DAYS`），不能选今天之后。超长时 picker 里禁用，不弹错误 |
| 来源 | 全部来源 / DSH / Claude Code / Codex | 全部 | 仅当 `agentModes.length > 0` 时显示；改了要重新请求（`scope` 参数） |
| 模型 | 多选（可搜索），选项 = 区间内有用量的模型，按积分降序 | 积分前 5 | 最多选 8 个（超过时禁用其余选项）。没选中的模型合并成一条「其他」（灰色，可在图例里显隐）。列表顶部「全部」快捷项不提供（超过 8 条就看不清） |
| 指标 | 积分 / token / 请求 | 积分 | token = 输入 + 缓存读 + 输出（与现有统计卡同口径）。一张图只有一个 y 轴（不做双轴） |
| 图形 | 折线 / 堆叠 | 折线 | 折线 = 每个模型一条线，看趋势；堆叠 = 每天一根堆叠柱，看构成和总量 |
| 合并渠道 | 开关 | 关 | 开 = 把 `模型@渠道` 按 `@` 前的模型本名合并（日汇总里的 `model` 是请求里的原名，可能带 `@slug`）；模型下拉、图、表同步按本名 |

筛选状态写进查询串（`?range=30&metric=cost&chart=line&models=a,b&merge=1&scope=dsh`；自定义区间用 `from`/`to`），刷新页面保持。用现有 `useTableQuery` 风格或 `vue-router` 的 `replace`，不要污染「使用记录」的 `page`/`pageSize`（用 `u_` 前缀或单独的键）。

**合计行**：区间合计「积分 · 请求 · token · 失败（>0 才显示）」，随来源/区间变化（不随模型多选变化——它是整个区间的合计）。

**图（自绘 SVG，组件 `components/relay/ModelUsageChart.vue`，新建；旧 `DailyUsageChart` 保留不删，别处可能在用）**

- 尺寸：宽 100%，高 280（≤ 600 宽时 220）。左侧 y 轴 4–5 个刻度（取整到好看的数：1/2/5×10ⁿ），刻度数字用 `formatPoints` / `formatTokensZh` / `formatCount`；网格线极浅（`--c-border`）。x 轴按区间长度取 5–7 个日期标签（`MM-DD`），不重叠。
- 折线：每条 2px，圆角连接；数据点只在悬停那天画 8px 圆点（带 2px 表面色描边）。某天为 0 也连线（0 是真实值，后端每天都补齐）。
- 堆叠：每天一根柱，段与段之间 2px 表面色间隙，顶端圆角 4px，柱宽随天数自适应（最小 2px）。「其他」放在最上面。
- 悬停：整列热区（比标记宽），竖向十字线 + 浮层：日期、每个可见系列的色块 + 名称 + 值（按值降序），底部「合计」。浮层夹在图内（参考 `DailyUsageChart.placeTip` 的做法，390 宽不能把页面撑出横向滚动）。键盘：图可聚焦，←/→ 移动当天。
- 图例：图下方一行，色块 + 模型名（等宽、单行省略、`title` 给全名）+ 区间合计；点击切换显隐（至少保留一条可见）。≤ 4 条系列时在折线右端直接标模型名（空间不够就省掉，不要重叠）。
- 空状态：区间内没有任何用量 → 图区域显示「这段时间还没有用量」，不画坐标。加载中：保留旧图并降低不透明度（与现有一致）。
- 无障碍：SVG `role="img"` + `aria-label` 概述（区间、模型数、合计）；下面的按模型表就是表格视图。

**配色（类目色，按「模型」固定，不按排名）**

颜色跟着模型走：取色顺序 = 本次区间内按积分降序的**首次出现顺序**，在页面会话内缓存 `模型 → 色位`，筛选掉某个模型不会让其余模型换色。6 个色位 + 「其他」灰，第 7、8 个选中的模型复用色位 1、2 并加虚线（`stroke-dasharray: 4 3`）作为第二编码。
新建 `styles/tokens.css` 里的图表令牌（已用 dataviz 校验脚本验证：浅色 6 色全过，暗色换 `#5b7cff` 后全过）：

| 令牌 | 浅色 | 暗色（`[data-theme='dark']` 注释块里一并写上） |
| --- | --- | --- |
| `--c-series-1` | `#4d6bfe` | `#5b7cff` |
| `--c-series-2` | `#eb6834` | `#d95926` |
| `--c-series-3` | `#1baf7a` | `#199e70` |
| `--c-series-4` | `#eda100` | `#c98500` |
| `--c-series-5` | `#e87ba4` | `#d55181` |
| `--c-series-6` | `#6a47c9` | `#9085e9` |
| `--c-series-other` | `#b6c0d6` | `#4a5675` |

浅色下 3、4、5 号对白底对比度 < 3:1，所以文字一律用正文色（`--c-text` / `--c-text-2`），颜色只用在线、柱、色块上；图例与表格始终在，不靠颜色单独区分。

**按模型表**（图下方，替换现有表）：列 = 色块 + 模型（等宽、省略）、请求、输入 / 缓存 / 输出（悬停给精确值，与现有一致）、积分、占比（数字 + 一根细的占比条）。随「合并渠道」「来源」「区间」变化；**不**随模型多选过滤（表里列全部模型，选中的模型行高亮，点行切换是否选中，超过 8 个时不能再选）。
现有「按来源」小表：开通了对话模式且「来源 = 全部」时，作为合计行下面的一行小标签（`DSH 52.1 · Claude Code 30.4 · Codex 3.5 积分`）显示，不再单独一张表。

### 2.3 ③ 可用模型

`RelayModelsTable` + `AgentModeModelsSection` 原样搬过来，不改。

### 2.4 ④ 搜索与抓取

`ToolsCard` 改成只显示三格：本月免费（`UsageBar`，`freeCallsPerMonth = 0` 时这一格换成「本月免费 —」）、本月调用（次）、本月花费（积分）。去掉：超出后单价、下发到 DSH、卡内说明句、逐条表、卡内刷新按钮（页头刷新统一刷）。总开关关闭时整卡不渲染（不变）。

### 2.5 ⑤ 使用记录

- 卡片标题「使用记录」，InfoTip「只记录模型、token、耗时和费用，不保存对话内容。」保留。
- 标签：「模型调用」（总有）、「搜索与抓取」（`ToolsUsageTable`，搜索池开着才有）、「算力租赁」（`ComputeLeaseTable`，`showCompute` 才有）。只有一个标签时不显示标签头。当前标签进查询串 `?log=calls|tools|compute`。
- 「模型调用」筛选行：日期区间（默认最近 30 天，最长 92×4 天，与后端一致）、来源（开通了对话模式才显示）、模型（下拉，选项来自 `relay.models` 的名字 + `routes` 展开的 `模型@渠道`，可搜索、可清空）、状态（全部 / 成功 / 中断 / 上游错误 / 请求错误）、「重置」。后端 `GET /api/me/relay/logs` 已支持 `from/to/model/status/scope`，用户端不需要改后端。
- 各标签分页互不干扰；「模型调用」沿用 `?page=&pageSize=`，其他两个标签页内自管分页（与现在一样）。

## 3. 后端（加法）

`GET /api/me/relay/usage` 与 `GET /api/admin/relay/usage` 的响应加：

```ts
/** 19 §3：按「天 × 模型」的明细，只给有用量的格子（没有的天前端补 0）；用户端与管理端都给。WP24 起总会给出 */
dailyByModel: z.array(RelayUsageBucketSchema.extend({ day: RelayDaySchema, model: z.string() })).optional()
```

- 实现：`repo.ts` 新增 `dailyBucketsByDayModel`（`GROUP BY day, model ORDER BY day ASC, cost DESC`），复用 `dailyWhere`（`userId` / `scope` 筛选照旧）。`service.usageStats` 里填上。
- 量级：92 天 × 几十个模型，几千行以内，无需分页。
- 不改表、不加迁移。

## 4. 不做

- 不做小时粒度（日汇总表只有天；逐条表做小时聚合留到以后）。
- 不做充值、流水重做（D2）。
- 不改管理端「用量」页（`RelayUsageTab`）；它想用 `dailyByModel` 以后再说。
- 不删任何组件、接口、mock 场景。
