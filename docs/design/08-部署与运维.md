# 08 部署与运维

> Hub 与全部用户容器跑在同一台 Linux 主机上（02 §3）。最小部署只有 systemd 用户服务 + 本机明文
> `http://127.0.0.1:7700`；要对外就再加一层反向代理与 TLS。
> 本文讲**为什么这么部署**；可照抄的步骤、systemd 单元、nginx/HAProxy 示例与故障排查在
> [`deploy/README.md`](../../deploy/README.md)。

## 1. 前置条件（一次性，需要 sudo）

```bash
# 1) 让跑 Hub 的用户能用 Docker（新开的终端才生效）
sudo usermod -aG docker "$USER"
# 2) 数据目录（不要在仓库里）
sudo mkdir -p /srv/dsh-hub && sudo chown "$USER:$USER" /srv/dsh-hub && chmod 750 /srv/dsh-hub
# 3) 出网规则（02 §4），装成开机服务 dshhub-egress.service（After=docker.service）
sudo deploy/nft/install.sh
# 4) 安全闸门（02 §3）——不通过就不开放注册，改走附录 A
scripts/security-gate.sh
```

`deploy/prereq.sh` 会把上面这些逐项检查一遍（只读，不改系统）。

## 2. 部署 Hub

### 2.1 生产副本与开发检出分开

生产目录只跑**一个固定的检出**，只在你决定升级时前移；开发检出怎么折腾都行：

```bash
# 首次：把仓库放进生产目录（worktree 或普通 clone 都行）
git clone <你的仓库> ~/dsh-hub-prod && cd ~/dsh-hub-prod
pnpm install --frozen-lockfile && pnpm -r build
# 之后每次升级
deploy/upgrade.sh
```

`upgrade.sh` 的顺序是：取新代码 → `pnpm install --frozen-lockfile` → `pnpm -r build` → 跑迁移 →
重启服务 → 健康检查；任何一步失败都会退回升级前的提交并重启旧版本。

### 2.2 hub-api 服务

用户级 systemd 单元（完整文件见 `deploy/systemd/dsh-hub.service`），关键几项：

```ini
[Service]
WorkingDirectory=%h/dsh-hub-prod
Environment=NODE_ENV=production HUB_DATA_DIR=/srv/dsh-hub HUB_PUBLIC_ORIGIN=http://127.0.0.1:7700 HUB_TLS_PORT=0
EnvironmentFile=-%h/.config/dsh-hub/hub.env
UnsetEnvironment=http_proxy https_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY all_proxy NODE_USE_ENV_PROXY
ExecStart=/usr/bin/env node apps/api/dist/main.js
Restart=always
RestartSec=3
```

- 站点相关的值（域名、TLS、边缘入口）一律写进仓库外的 `~/.config/dsh-hub/hub.env`（0600），单元里只留
  本机默认值；前缀 `-` 让文件不存在也能启动。
- `Restart=always` 而不是 `on-failure`：进程被外部 SIGTERM 时退出码是 0，`on-failure` 不会拉起。
  `systemctl --user stop` 不受影响。
- `systemctl --user` 需要 `loginctl enable-linger "$USER"` 才能在未登录时存活；用户服务继承的附加组
  里已经有 `docker`，不用 `sg`。

```bash
systemctl --user daemon-reload && systemctl --user enable --now dsh-hub
deploy/hubctl create-admin --username <你的用户名>   # 交互输入密码
journalctl --user -u dsh-hub -f
```

首次启动会自动生成 `secrets/master.key`（所有加密字段都靠它派生，**丢了就解不开**，备份要跟上）。
然后打开 `http://127.0.0.1:7700/admin`，在「DSH 版本」构建第一个运行时镜像。

## 3. 对外入口（概要）

两种接法二选一，细节与配置示例见 [`deploy/README.md`](../../deploy/README.md)：

| 接法 | Hub 侧 | 代理侧 | 真实 IP 来源 |
| --- | --- | --- | --- |
| 四层透传，Hub 终结 TLS | `HUB_TLS_PORT=7443`、`HUB_PROXY_PROTOCOL=true`，证书在 `secrets/tls/` | `send-proxy`（HAProxy）/ `proxy_protocol on`（nginx stream） | PROXY v1 头 |
| 七层终结，走边缘入口 | `HUB_EDGE_PORT=7720`、`HUB_EDGE_ORIGIN=https://…` | 终结 TLS、写 `X-Real-IP`、明文转发 | `X-Real-IP` |

要点：

- **只信规定的来源**：7443 只认 PROXY v1，边缘入口只认 `X-Real-IP`，任何 `X-Forwarded-*` 都不信（02 §5）。
- **CSRF 与 cookie 按入口区分**：公网请求只认 `HUB_PUBLIC_ORIGIN`（边缘入口认 `HUB_EDGE_ORIGIN`），
  Secure/HSTS 也只对公网响应生效。
- **证书**：`deploy/tls/issue-cert.sh`（acme.sh + DNS-01）签好装进 `secrets/tls/`，`SIGHUP` 热换，不重启；
  没有正式证书时 Hub 用一张临时自签证书兜底。
- 反向代理要透传 WebSocket（`Upgrade` / `Connection`）并关掉响应缓冲，手机通道与会话都靠它。

## 4. 开发与生产在同一台机器上的隔离约定

| 维度 | 生产 | 开发 / 测试 |
| --- | --- | --- |
| 代码 | `~/dsh-hub-prod`（固定检出） | 开发检出与其 `.data/` 目录 |
| 数据 | `/srv/dsh-hub` | 各检出的 `.data/`、测试临时目录 |
| 端口 | 7700（+7443 / 7720） | 7701 起另选，测试优先用 `app.inject` 不监听端口 |
| 容器 / 网络 / 镜像 | `dshhub-u*` / `dshhub-users`（`HUB_USERS_SUBNET`）/ `dshhub/runtime:*` | `dshhub-test-*` / 另一个网段 / 可复用 `dshhub/runtime:*`（只读使用） |
| 环境标识 | `HUB_ENV_ID=prod`、`HUB_CONTAINER_PREFIX=dshhub-` | `HUB_ENV_ID=test`/`e2e`、`HUB_CONTAINER_PREFIX=dshhub-test-`（容器标签 `dshhub.env` 隔离对账与回收） |
| 出网规则 | 只匹配生产用户网段 | 开发网络的容器不受限（只跑测试数据） |

同一台机器上还跑着别的服务时，注意不要占用 Hub 的端口与网段；Hub 只管理带自己前缀的容器与网络。

## 5. 备份

| 对象 | 方式 | 频率 | 保留 |
| --- | --- | --- | --- |
| `hub.db` | `deploy/hubctl db:backup`（SQLite `VACUUM INTO`） | 每天 03:30 | 14 天 |
| `secrets/` | 随 db 一起打包（0600） | 每天 | 14 天 |
| `users/*/workspace` + `home/.dsh/sessions` | `tar --listed-incremental` 到**另一块盘**（`HUB_BACKUP_DIR`） | 每天 04:00 | 7 天 + 4 周 |

由 `deploy/systemd/dsh-hub-backup.timer` 触发；恢复用 `scripts/restore-db.sh`（停服 → 留档 → 换库 →
完整性检查）。每月做一次恢复演练（10 §G）。

## 6. 监控与日志

- hub-api 日志：pino JSON → journal；`journalctl --user -u dsh-hub`。
- `/api/admin/overview` 即运维面板；`node apps/api/dist/cli.js doctor` 做逐项自检。
- 告警（可后加）：反向代理到 Hub 的连接断开 > 60 秒、Docker 不可用、磁盘可用 < 50GB、某用户实例连续
  3 次启动失败 → 管理后台顶部红条。

## 7. 常用运维命令

```bash
systemctl --user status dsh-hub dsh-hub-cert.timer dsh-hub-backup.timer
docker ps --filter label=dshhub.managed=1 --format 'table {{.Names}}\t{{.Status}}\t{{.Image}}'
docker stats --no-stream $(docker ps -q --filter label=dshhub.managed=1)
deploy/hubctl user:list | user:reset-password <username> | instance:stop-all | db:backup
node apps/api/dist/cli.js doctor
```

## 附录 A：B 计划——换一台专用主机

仅当安全闸门（02 §3）不通过时启用。要点：

1. 新主机只跑 Hub 与用户容器：不挂其它数据盘、不加入办公网、只开必要端口。
2. 数据迁移：停服后拷 `hub.db` + `secrets/` + `users/`，或在旧机跑 `scripts/backup.sh` 再在新机
   `scripts/restore-db.sh`（Hub 用 SQLite，没有独立的数据库服务）。
3. 容器引擎可以换 podman（Docker 兼容 API）：`DOCKER_HOST=unix:///run/podman/podman.sock`，
   代码里的驱动只用 Docker Engine 的常用子集；nft 规则同样适用。
4. 域名/证书在代理层重建即可，Hub 侧只需要改 `HUB_PUBLIC_ORIGIN`（以及边缘入口那两个变量）。
